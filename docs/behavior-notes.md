# 线上行为规格笔记（zhuyidao.net 实测）

数据：`bench/data/probes.jsonl`（约 170 次请求，2026-09-15），重放脚本 `bench/probe_api.py`。
恒等式抽样经 mpmath 40 位验证全部精确成立——返回参数**确实满足**渲染出的恒等式
（此前"e 型参数不满足恒等式"的观察是探测方字段名 bug：误用 `constant=` 导致缺省回退 pi）。

## 1. 协议层

### POST /calculate 表单字段

`type, power, comparison, rational`，全部 urlencoded。

- **`type` 缺失时静默回退 pi**（响应 `"type":"pi"`），`type` 存在但未知 → 400 `无效的证明类型`。
- `comparison` 只认 `>`、`<`；`=` → 400 `无效的不等号方向`。
- `power`、`rational` 只接受非负整数或 `n/d`（分子分母均须为十进制数字串）：
  - 空串 / `abc` / `3.14`（小数）/ `-1/10`（负）→ 400 `右侧有理数格式无效`；
  - `1/-2`（分母带负号）→ 400 `右侧有理数格式无效`；power 侧同则报 `左侧系数格式无效`；
  - `1/0` → 400 `右侧有理数分母不能为0`；
  - 分子或分母 ≥ 10^16 → 400 `右侧有理数请输入小于10^16的整数或分数`。
  - `0/5` 合法（解析为 0），随后按方向判定走求解路径。
- **负数界无法表达**：rational 不接受负号 ⇒ 目标常数为负的类型（tan2、cot2、sin4、cos4 等）
  事实上无法被证明；且下列类型在服务端做值域检查（HTTP 404，错误体同样只有 `{"error":...}`）：

  | type | 合法 power | 越界错误原文 |
  |---|---|---|
  | ln_q, ln_q_square | q > 1 | `请在ln后输入一个大于1的数` |
  | sin_q | q ∈ (0,π) | `请在sin后输入一个在(0,π)内的数` |
  | cos_q | q ∈ (0,π/2) | `请在cos后输入一个在(0,π/2)内的数` |
  | tan_q, cot_q | q ∈ (0,π/2) | `请在tan后输入一个在(0,π/2)内的数`（cot 同理） |
  | sin_pi_q, cos_pi_q | 真分数 q ∈ (0,1/2)，整数也不行 | `请在输入一个在(0,1/2)内的分数，本情况不支持整数` |

  即"tan_q/cot_q 在 cos/sin 变号处怎么处理"的答案是：**直接拒绝，不存在变号处理**
  （q=2、q=4、q=7 均被 404 拒绝）。sin_pi_q q=1/2、2/3、3/5、负值同样全部被拒——
  kernel-spec 中"0<q<1/2"就是硬边界，q≥1/2 不做归约、直接 404。

- `arctan_q` power=0 → **500 `服务器内部错误，请稍后再试`**（核退化导致求解器崩溃，
  是唯一观测到的 /calculate 500）。

### 响应形态

- 成功 200：`{success:true, type, equations:{solution}, parameters:{m,n,a_val,b_val,c_val,au_val,bu_val,cu_val,u_val,unified_form}}`。
- 求解失败/方向错/值域拒绝 → **HTTP 404**，body 仅 `{"error":"..."}`，**无 `success` 字段**
  （api-spec 里"{"success":false,...}"的描述不准确：错误响应没有 success 键）。
- 输入格式错 → **HTTP 400**，同样仅 `{"error":...}`。
- `equations.solution` 格式：线性 P 写 `"a = 47/120, b = -13/120"`；
  二次 P 写 `"a = 549/154, b = -513/352, c= 1161/2464"`（注意 `, c= ` 处无空格、`c=` 后有空格）。
- `a_val` 是 `au_val/u_val` 约分后的分数串（如 `566/5` 对应 `1698/15`）；
  `u_val`、`au_val` 等为字符串，`m,n` 为整数。
- **`unified_form` 在全部 76 个成功响应中恒为 `{}`**——/calculate 路径上是死字段。
- `GET /get_integral_image` 必须用 GET + query；对它 POST 表单 → 500。
- 缺省回退：`type` 字段缺失 → 按 pi 求解（见上）；其它字段缺失走各自格式错误。

## 2. (m,n) 搜索顺序

证据（全部摘自 probes.jsonl，`tag=mn_order:*`）：

- pi（基 x^{2m}(1-x²)^n）：`>3`→(1,1)；`<4`→(0,0)；`>31/10`→(1,2)；`<32/10`→(1,1)；
  `<22/7`→(3,3)；`>223/71`→(2,4)；`>314159/100000`→(5,6)；`<355/113`→(5,8)；
  `<312689/99532`→(9,12)；d≈7e-16→(13,18)；d≈3e-17→(15,18)。
- e（基 x^m(1-x)^n）：`>2`→(0,0)；`<3`→(0,1)；`>5/2`→(0,1)；`<11/4`→(1,1)；
  `>27/10`→(1,2)；`>271828/1e5`→(3,4)；d≈4.5e-14→(6,6)；d≈4.3e-16→(2,3)。
- ln2：`>3/5`→(0,1)；`<7/10`→(2,0)；`<694/1000`→(2,2)；`>6931/10000`→(2,3)。

结论：

1. 与作者自述一致：**返回的 (m,n) 是该顺序下第一个使 P 定号的解**。
   m+n 随松紧度整体上升（同界内 m+n 从小到大），同 m+n 时更平衡的优先——
   (2,4)、(5,8)、(9,12) 等不对称命中都意味着 (3,3)/(6,7)/(10,11) 等更平衡的同和候选先失败。
2. **无反例，但两点不能钉死**：(a) |m−n| 相同的两支谁先——观测到 ln2 用 (2,0)（m>n），
   pi/e 所有不对称命中都是 n>m，均兼容"同差值时 m 大者优先"（engine.py 的 `-m` 排序）；
   (b) 方向与紧度的相互作用。
3. **(m,n) 不随紧度单调增长**：e 在 d≈4.5e-14 时要 (6,6)，在 d≈4.3e-16 时却 (2,3) 即成——
   因为界越紧，"恰好定号"靠运气；实现上 parity 对 golden 的 (m,n) 命中率会受这种 luck 支配。
4. 方向反的判据先行：`pi_n 2 > 9869604401089358/1e15`（真方向，d≈6e-16）返回
   `要证明的式子不等号方向反了`——说明搜索中遇到 P≤0 的解即提前抛 WrongDirection，
   而不是搜完再报"未找到"。**WrongDirection 会抢在 NoSolution 之前触发**（engine.search 现有语义与此一致）。

## 3. 指数上限

- 报错文案：`在指数不超过10的范围内未找到{>或<}方向的解`（HTTP 404），数字写死在文案里。
- 文本级确认上限 10 的类型：e_pi、sin_pi_q、arctan_q、gamma、varpi、gauss、
  以及 ln_q 在 q=257（结构性失败：界不紧也大 q 需要高指数）。
- **上限是按单个指数计的，不是 m+n**：pi 在 d≈3e-17 时用了 (15,18)，m+n=33>30 仍成功。
- pi/e/e_q/sin_q 在输入上限（10^16）允许的最紧界内从未失败：
  pi (15,18)@3e-17、e (2,3)@4e-16、e_q (9,9)@4e-16、sin_q (6,7)@1e-16。
  "e/pi=30" 与数据相容但**未能直接证实**（受输入上限限制，最紧可表达界约 1e-16~1e-17，
  而 pi 在 n=18 处仍能证）；e_q/sin_q 是否 10 同样未证实（只证得下界 ≥9/≥7）。
- gamma/varpi/gauss 在 d≈1e-6 即失败——这三类还有结构性约束（核固定形状），不只松紧度。

## 4. power 语义

| 类别 | power 含义 | 证据 |
|---|---|---|
| 常数类 pi, e, gamma, golden, catalan, zeta3, e_pi, varpi, gauss | **系数 k**：证 k·C vs r | pi 8 `<26` → `26 - 8\pi = ∫x²(1-x²)(11-5x²)/(x²+1)`；e_pi 2 `<47` → `47 - 2e^{\pi}`；gamma 2 `>1/2` 成功（若当指数算 γ²=0.33<0.5 应方向错）；e 2 `>16/3` → (1,1) P=2x/3 证 2e>16/3 |
| pi_n | **指数 k=p/q**；q≠1 时证 π^p vs r^q | 见下 |
| e_q, ln_q, ln_q_square, sin_q, cos_q, tan_q, cot_q, sinh_q, cosh_q, tanh_q, coth_q, arctan_q, arccot_q, artanh_q, arcoth_q, sin_pi_q, cos_pi_q, sin_q_degree, cos_q_degree | **参数 q**（分数允许） | e_q `3/2 <9/2` 成功（e^{3/2}=4.4817）；ln_q 前端/服务端都要求 q>1 |

**pi_n 分数指数**：`power=5/2` 时服务端证的是 `(π^{5/2})² vs r²`，即 π^5 vs r²：

```
>17 → (1,0): (π^{5/2})² - 17² = ∫x²(7371x²+6859)ln⁴(1/x)/(40(1+x²)) dx > 0
<18 → (0,0): 18² - (π^{5/2})² = ∫(135x²+7)ln⁴(1/x)/(10(1+x²)) dx > 0
>20, >98, >100 → 方向反了（17²=289<306<400=20²、98²、100²，方向判定按平方后比）
```

核用整数指数 k=分子（ln^{k-1}）。前端 alert"计算π的5次方"的说法不准确——分母参与平方界。
方向判定的真相：`π^{5/2} > 17 ⟺ π^5 > 289`（两边非负时成立）。

## 5. 各类型网格形状（图像证据）

`f(x) = B_{m,n} · P · K`，下面给出返回 (m,n) 到实际指数的映射：

- **pi**：`x^{2m}(1-x²)^n · (au+bu·x²)/u / (1+x²)`。m→2m。(5,8)→x^{10}(1-x²)^8；
  (13,18)→x^{26}(1-x²)^{18}。
- **e / e_q**：`x^m(1-x)^n · (au+bu·x)/u · e^{qx}`。(1,2)→x(1-x)²；(2,2)@e_q2→x²(1-x)²e^{2x}。
- **pi_n k**：`x^{2m+δ}(1-x²)^n · (au+bu·x²)/u · ln^{k-1}(1/x)/(1+x²)`，
  **δ = 1（k 偶）/ 0（k 奇）**——即 x 指数与 k 奇偶相反：k=2 → x^{2m+1}（(2,2)→x⁵ ln¹），
  k=5 → x^{2m}（(1,0)→x² ln⁴）。
  ⚠️ 与 kernel-spec 的 `x^m(1-x²)^n，m+k 奇` 不符——返回的 m 不是 x 的指数，
  指数恒为偶/奇由 k 的奇偶决定（k 偶需奇次幂落入 η 空间、奇需偶次幂落入 β 空间）。
- **catalan / zeta3**：同 pi 核族；zeta3 (2,2)→`x⁵(1-x²)² ln²x/(4467(1+x²))`（奇次幂 x^{2m+1}）。
- **sin_q / cos_q / tan_q / cot_q / sinh_q / cosh_q / tanh_q / coth_q**：
  `x^m(1-x)^n · (au+bu·x+cu·x²)/u · sinh-或-sin 核`；tan/cot/tanh/coth 的核是 sin(qx)/sinh(qx)，
  **方程里整体乘 1/cos q（或 1/cosh q）前置因子**：
  `15 - tan(3/2) = ∫ [1/cos(3/2)]·x²(1-x)²(1161x²-3591x+8784)sin(3x/2)/2464`；
  `4/5 - tanh1 = ∫ [1/cosh(1)]·(1-x)(2-x²)sinh(x)/5`。
- **sin_pi_q / cos_pi_q / sin_q_degree / cos_q_degree**：域 [0,π/2]，
  `sin^m x·(1-sin x)^n·(au+bu·sin x)/u·sin(αx)`；
  sin 侧 α=1−2q̃，cos 侧 α=2q̃（q̃=q 或 度数/180）。
  **返回的 `c_val` 此时是核频率 α，不是多项式系数**（sin_pi_q 1/5 → c_val=3/5；
  sin_q_degree 45 → c_val=1/2；cos_q_degree 60 → c_val=2/3），
  多项式第三系数由 cu_val 表示（这些 case 下 cu_val=0）。
- **e_pi**：域 [0,π]，`sin^m x(1-sin x)^n (au+bu·sin x)/u · e^x`；(2,5)→sin²x(1-sin x)⁵。
- **ln_q**：`x^m(1-x)^n (au+bu·x)/[u·(1+(q-1)x)^s]`，s 见下节。
- **ln_q_square**：`x^m(1-x)^n (au+bu·x+cu·x²)·log(1+(q-1)x)/[u·(1+(q-1)x)^s]`。
- **varpi**（上界）：`x^{4m+3}(1-x)(au+bu·x⁴)/[u·√(1-x⁴)]`；(6,1)→x^{27}。
- **gauss**（下界）：`x^{4m}(1-x)(au+bu·x⁴)/[u·π√(1-x⁴)]`；(2,0)→x⁸。
  ⚠️ 这两类 `(1-x)` 是结构因子：**gauss n=0 时仍显示 (1-x)**，n 的角色未被图像直接揭示
  （varpi n=1、(1-x)¹ 不可区分）；parity 实现需自验 n 的语义。
- **gamma**：两段式积分，返回 (m,n) 属于**第二段**（ln(n+1) 子证明的 x^m(1-x)^n 部分），
  第一段指数另行决定：`<3/5` → (2,4)，第一段 x⁵；`cu_val=5` 是 ln6 子核 (1+5x)^4 的 c=q−1。
  ⚠️ `gamma 2 > 1/2` 返回 `m=n=0, a_val=1/4, c_val=1, u_val="0", au/bu/cu=0`，
  且 `equations.solution="a = 0, b = 0"`——退化路径下字段互相矛盾，golden 需特判。

## 6. ln_q 的分母幂 s（含 artanh/arcoth 归约）

从方程直接读出 `s`（核 `(1+(q-1)x)^s`）：

| case | q | 界距 d | s | (m,n) |
|---|---|---|---|---|
| ln_q <7/10 | 2 | 6.9e-3 | 2 | (2,0) |
| ln_q <2773/4000 | 2 | 1.0e-4 | 3 | (2,3) |
| ln_q >6931/10000 | 2 | 4.7e-5 | 3 | (2,3) |
| ln_q <11/10 | 3 | 1.4e-3 | 3 | (2,3) |
| ln_q <161/100 | 5 | 5.6e-4 | 5 | (5,3) |
| arcoth 2 <3/5 | →ln3 | 5.1e-2 | 1 | (1,1) |
| artanh 1/2 <11/20 | →ln3 | 6.9e-4 | 3 | (2,3) |
| ln_q_square <49/100 | 2 | 9.5e-3 | 2 | (0,2) |
| ln_q_square <121/100 | 3 | 3.1e-3 | 4 | (1,4) |

规律：**s 与 (m,n) 一样是被搜索的自由度**，随 q 与紧度增长；s 可小至 1。
ln_q 在 q=257、界距 9e-4 时已越上限失败（大 q 需要大 s/指数）。
未钉死：s 的迭代顺序（疑为外层 s 升序 + 内层 (m,n) 标准序）；ln_q 界很松时 s 下限是 1 还是 2。

## 7. arc 归约的写法（方程保持 arc 记号，参数给归约后的 ln/arctan 参数）

- `artanh_q q` → 证 `ln((1+q)/(1−q))/2`：q=1/2 → ln3/2；返回 `c_val=3`（归约后的 ln 参数），
  方程仍写 `artanh(1/2)`。与 `ln_q 3 <11/10` 对照：同一 (m,n)=(2,3)、同一 (2x+1)³ 核，
  P 恰好减半（(20x+3)/45 vs (40x+6)/45）——即直接把 ln 恒等式系数 /2。
- `arcoth_q q` → `ln((q+1)/(q−1))/2`：q=2 → ln3/2，`c_val=3`，方程写 `arcoth 2`。
- `arccot_q q` → `arctan(1/q)`：核 `∝1/(x²+q²)`（渲染成 `20x²+80=20(x²+4)`），
  方程写 `arccot 2`，`c_val=0`（偶核 P=a+bx² 两参）。
- 即 arc 家族**不归约显示名，但内部完全按归约后目标求解**；`c_val` 对 log 归约类携带
  归约后的对数参数，对 arccot 不用。

## 8. 方向判定与失败语义

- 方向错 → 404 `要证明的式子不等号方向反了`（快，~150-300ms，因为靠前的 (m,n) 就给出 P≤0）。
- 真方向但超紧：pi_n 2 在 d≈6e-16 时同样返回"方向反了"（P≤0 解先被命中，见 §2.4）。
- `e > 3/1`（假命题）、`e < 8/3`（假命题）、`pi < 0` 均 → 方向反了。
- `equations.solution` 与 parameters 在退化 case 可不一致（gamma2：`solution` 写 `a = 0, b = 0`
  但 a_val=1/4）——实现时以 parameters 为准、并复现这个不一致。

## 9. 计时

`/calculate` 中位数 261ms、均值 756ms、最大 6.9s（sin_pi_q 紧界）；
ln_q/三角/双曲系普遍 1-4s（矩展开贵），pi/e/quadlog 系 100-300ms；
`/get_integral_image` 恒 ~200ms。服务端有前端提示"可能需要30秒"的长尾。

## 10. 与 kernel-spec/api-spec 的差异（实现易发 bug 点）

1. kernel-spec pi_n 基 `x^m(1-x²)^n，m+k 奇` ⇒ 实测为 `x^{2m+δ}(1-x²)^n`，δ=1 当 k 偶、0 当 k 奇。
2. kernel-spec 说 varpi/gauss 基里 `(1-x)` 的指数：实测 `(1-x)` 恒为一次结构因子，
   返回 n 不直接是它（gauss n=0 仍显示 (1-x)）。
3. api-spec 称失败返回带 `success:false`：实测错误 body 只有 `{"error"}`，HTTP 400/404/500。
4. api-spec 未记：type 缺失回退 pi；`10^16` 输入上限；各类型 power 值域检查与错误文案；
   负号一律格式无效；`unified_form` 恒空；c_val 对 trig_pi/degree/arc-log 类型是核参数而非系数。
5. "方向反了"不仅在用户填错时出现——真方向极紧界（pi_n）也会触发，取决于 (m,n) 命中次序。
6. s（ln 类分母幂）是搜索自由度而非固定值，kernel-spec 只提"可升幂"未给搜索规则。
7. pi_n 分数指数走"升幂比较"（π^p vs r^q），不是忽略分母。
