# decompose_exact: every registered type as an atom (W7-decomp-ext)

`decompose_exact.py` now accepts every kind that `solve.prove(..., exact=True)` can certify — all of `kernels.EXACT_TYPES` plus the site-registered function kinds the site parser never spelled out (`cot_q`, `cosh_q`, `coth_q`, `arccot_q`, `artanh_q`, `arcoth_q`, `sin_pi_q`, `cos_pi_q`, `sin_q_degree`, `cos_q_degree`, `ln_q_square`). `decompose.py` is byte-frozen site parity and is untouched: the extended kind sets, the parser, and the domain gate all live in `decompose_exact.py` alone. The site path still rejects every new spelling (`tests/test_decompose_exact.py::test_site_path_still_rejects_exact_spellings`).

## Atom semantics

The unit model is unchanged — every sub-claim certifies `U ⋚ β` with `U = constant_mpf(kind, power)`:

- Coefficient kinds (`power = q·C`, the `pi`/`e` pattern): `zeta5`, `zeta7`, `zeta9`, `zeta11`, `beta4`, `beta6`, `beta8`, `beta10`, `pi_sqrt2`, `pi3`, `pi3_u`, `pi3_a`, `gamma14`, `gamma34`, `gamma12`. A term `c·a` folds `|c|` into the power slot and proves `|c|·C ⋚ β`.
- Argument kinds (`power = q`, the `ln_q` pattern): `ln_q_square`, `ln_q_cube`, `ln_q_quad`, `arcsin_q`, `arsinh_q`, `gaussint_q`, `dawson_q`, `erfiint_q`, `li2_q`, `psi1_q`, `si_q`, `cin_q`, and the ten site function kinds listed above.

One change to pre-existing behavior: `arg < 0` is read as a reciprocal factor only for the exponent kinds `pi_n`/`e_q` (`EXPONENT_KINDS`). Signed-domain function kinds (`SIGNED_ARG_KINDS`: `arsinh_q`, `si_q`, `cin_q`, `gaussint_q`, `dawson_q`, `erfiint_q`, `li2_q`, `sinh_q`, `cosh_q`, `tanh_q`, `arctan_q`, `arccot_q`) pass `q` to the power slot with its sign, because their exact kernels prove the literal signed claim — `sicin` folds `σ = sign(q)`, `invhyp`/`hyperbolic` fold parity, `li2`/`quadlog` handle signed `q` directly. Before this change any negative function argument was silently mis-modeled as a reciprocal (`si(-2)` would have been decomposed as a `1/Si(2)` factor), a soundness bug in the original exact path; the reciprocal reading is correct only for `π^n`/`e^q` where `U` is genuinely `1/base^|q|`. Remaining negative args (`sin(-1)`, `coth(-1)`, `ln(1/2)`) hit the domain gate below.

## Spellings

Parse order in `parse_atom_exact`: `EXACT_BASE` symbols → `Pow` handling → `Function` handling → fall through to the site's `parse_atom` unchanged.

| Spelling | Atom | Notes |
|---|---|---|
| `zeta5` `zeta7` `zeta9` `zeta11` `beta4` `beta6` `beta8` `beta10` `pi_sqrt2` `pi3` `pi3_u` `pi3_a` `gamma14` `gamma34` `gamma12` | bare coefficient-kind names | symbols in `EXACT_LOC` |
| `zeta(k)` k ∈ {3,5,7,9,11} | `zeta3`, odd zeta kinds | the builtin `zeta` stays unmapped so `zeta(2k)` still auto-evaluates |
| `dirichlet_beta(k)` k ∈ {2,4,6,8,10} | `catalan`, `beta4`–`beta10` | the builtin never auto-evaluates under sympify |
| `Gamma(1/4)` `Gamma(1/2)` `Gamma(3/4)` | `gamma14`, `gamma12`, `gamma34` | `Gamma` is an undefined `Function`; builtin `gamma` is deliberately left unmapped (it would auto-evaluate) |
| `asin`/`arcsin`, `asinh`/`arsinh`, `gaussint`, `dawson`, `erfiint`, `li2`, `psi1`/`trigamma`, `si`/`Si`, `cin`/`Cin`, `cot`, `cosh`, `coth`, `arccot`/`acot`, `artanh`/`atanh`, `arcoth`/`acoth`, `sinpi`, `cospi`, `sind`, `cosd` | function kinds | dual-name spellings follow the site's `ln`/`log`, `arctan`/`atan` convention; `sinpi(q)`/`cospi(q)` mean `sin(πq)`/`cos(πq)`, `sind`/`cosd` take degrees |
| `ln(q)^2` `ln(q)^3` `ln(q)^4` (also `log`) | `ln_q_square`, `ln_q_cube`, `ln_q_quad` | `Pow` with a `ln`/`log` `Function` base and integer exponent; `e=1` collapses to plain `ln_q` before parsing, other exponents raise `ERR_ATOM` |
| `EulerGamma` `GoldenRatio` `Catalan` `E` | `gamma`, `golden`, `catalan`, `e` | sympy builtins folded onto the atom symbols by `SYMPY_CONST` |
| `zeta(2k)`, `sqrt(pi)`, `pi^a` generated by sympy | `pi_n` family | `zeta(4)` sympifies to `π⁴/90` with the *real* `sympy.pi`; `SYMPY_CONST` substitutes builtin constants (`π`, `e`, `EulerGamma`, `Catalan`, `GoldenRatio`) onto the atom symbols after `sp.expand`, so these land as ordinary terms — `zeta(4) > 1` becomes the claim `π⁴/90 > 1` with a `pi_n(4)` atom |

Every function spelling must be an *undefined* `Function` in `EXACT_LOC` — mapping `arcsin` to the builtin would let sympy auto-evaluate `asin(1/2) → π/6` and silently re-parse as a `pi` coefficient atom. The `zeta`/`log` names are left unmapped on purpose (see table).

## Domain gate

`ATOM_DOMAIN` mirrors each kernel's `check_input`: `ln_q*` `q>1`; `arcsin_q`/`artanh_q` `(0,1)`; `arcoth_q` `q>1`; `psi1_q`/`coth_q` `q>0`; `li2_q` `q<1, q≠0`; `sin_q` `(0,π)`; `cos_q`/`tan_q`/`cot_q` `(0,π/2)`; `sin_pi_q`/`cos_pi_q` `(0,1/2)`; `sin_q_degree`/`cos_q_degree` `(0,90)`; `arctan_q`/`arccot_q`/`sinh_q`/`cosh_q`/`tanh_q`/`arsinh_q`/`gaussint_q`/`dawson_q`/`erfiint_q`/`si_q`/`cin_q` `q≠0`. The gate runs at parse time on every atom (both sides): the allocator needs every atom's unit value before any prove call, and `constant_mpf` leaks complex `mpc` (`log(-1)`, `asin(2)`, `polylog(2,1.5)`), `nan` (`cin(0)`), or `ZeroDivision` (`psi(1,-1)`) for out-of-domain `q` — without the gate those surface as 500s or silently wrong slack. Rejection text: `"{kind} 不接受参数 {arg}：超出核定义域"` (a `ValueError` → HTTP 400 on the server path). Exponent kinds and pure coefficient kinds need no gate — `pi^70`, `zeta5`, `e^(-3)` are always real.

## Verified coverage

`tests/test_decompose_exact.py` now parametrizes one proven single-atom claim per admitted kind (all pass — each takes the direct single-atom path, one `prove` call), plus signed-argument atoms (`si(-2)`, `arsinh(-1)`, `li2(-1)`, `sinh(-1)`, `tanh(-1)`, `arctan(-1)`, `cosh(-1)`), a function atom inside a sum (`ln(3)^3 + zeta5 > 2`), a product of new coefficient kinds (`pi*zeta5 > 16/5`), coefficient folding (`2*zeta5` → power slot `2`), pair mode across new kinds (`si(1) > cin(1)`), twelve rejection cases, and the site-path guard. A certified-false claim on a new kind (`pi3_u > 7/10`, `U ≈ 0.6845`) reports `claim_certified_false` honestly.

## Exclusions and limits

- `ln(q)^e` for `e ≥ 5` and `dirichlet_beta(k)` for `k` outside {2,4,6,8,10} raise `ERR_ATOM` — no registered kernel.
- `zeta(k)` for even `k` is not a zeta atom — it arrives as `π^(2k)/r` via sympy evaluation and decomposes as a `pi_n` term (e.g. `zeta(4)` → coefficient `1/90` on `pi_n(4)`), which is usually the better certificate anyway.
- Exact-constant powers (`zeta5^2`) raise `ERR_POW_SPECIAL`, matching the site's rule for `gamma^2`-style shapes.
- Function atoms are still banned inside product terms (`li2(1/2)*pi` → `ERR_ATOM`), same as the site.
- Pair mode (`atom ⋚ atom`) rejects negative exponent args (`pi^(-2) > e` cannot be modeled as `1/U`) but accepts signed-domain kinds on either side.
- `e_q(2)` is not a spelling — the site writes `e^2`/`exp(2)`; unchanged.
- The `varpi`/`gauss`/`gamma`/`e_pi` coefficient kinds were already admitted via `COEF_KINDS`; their `>`-fallback and composite (`gamma14`/`34`/`12`, `prover="composite"`) or Padé (`prover="pade"`) certificates pass through into `steps[].prover` unchanged.
