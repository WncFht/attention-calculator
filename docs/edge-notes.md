## 1. 相等判定（EqualClaim）的可达范围

`{"error":"二者相等"}`（HTTP 404）只在精确有理相等处触发， 覆盖类型里唯一可达的是 Niven 点：

- `sin_pi_q 1/6`、`cos_pi_q 1/3`、`sin_q_degree 30`（界 1/2）→ 404 二者相等， 两个方向同报（golden 已有 6 条）；本批追加 `cos_q_degree 60` 双向同样命中。
- `sin_pi_q 3/6`（未约分的 1/2）→ 不报相等，报值域 404 `请在输入一个在(0,1/2)内的分数，本情况不支持整数`——先约分后做开区间检查。
- 其余类型 power=0 + 界=常数·0 的各种"恰好相等"组合均不触发二者相等： pi/e/golden 等 `0·C vs 0` 走退化 200（解 `a = 0, b = 0`），gamma/双曲/arc 系走 500。
- **float64 相等的界不触发相等**：pi < 884279719003555/281474976710656 （即 float64(π) 的精确有理值）→ 404 `在指数不超过30的范围内未找到<方向的解`。 相等判定是精确有理比较，float 等值会漏进搜索。

## 2. 指数上限（cap）实测文案

`在指数不超过N的范围内未找到{方向}方向的解`（404）实测到的 N：

- **N=30**：pi、e（float 等值界耗尽搜索后自报）。
- **N=10**：pi_n、cos_q、e_q、zeta3、arctan_q、ln_q。
- pi 单个指数计（m≤30 且 n≤30）：golden 已见 m+n=33>30 成功，与上限一致。

## 4. /calculate 数值字段的空白与字符集

站端数值字段（power/rational）的解析等价于 **`s.replace(" ", "")` 后过 `^\d+(/\d+)?$`**（Python `re`，`\d` 认全角数字，`$` 容忍一个尾随换行）：

- 接受：`"22 /7"`、`"22/ 7"`、`"22 / 7"`、**`"2 2/7"`（数字内部空格也删）**、 `"1 / 2"`、前导/尾随空格、`"22/7\n"`（尾随换行）。
- 拒绝：`"\t22/7"`（tab 不被删，regex 失败 → 400）、`"22/7/1"`、`"22/"`、`"/7"`、 `"１／２"`（全角斜杠不是 `/` → 400；但全角**数字** `"１２"`、`"２２/７"` 接受 → 200）。
- `+3` / `-1` → 400 格式无效（regex 无符号位）；`"03"`、`"00"`、未约分 `"4/2"` 合法。
- 界 ≥10^16 是**严格**比较：分子/分母 `9999999999999999` → 正常走求解； `10000000000000000` → 400 `…请输入小于10^16的整数或分数`。

## 5. /get_integral_image 校验层（逐字段 400，全部钉死）

- **方法**：只收 GET+query；POST 表单 → 500；PUT/DELETE → 500；尾随斜杠路径 → 404。
- **校验顺序**（成对探针）：type → comparison → 整数字段组（m,n,u_val,au_val,bu_val,cu_val） → 分数字段组（a_val,b_val,c_val）。`type=foo&m=abc` 报 type；`m=abc&comp='='` 报 comp； `comp='='&a_val=abc` 报 comp。组内字段顺序未单独钉死。
- **type**：缺失缺省 `pi`；显式 `''` → 400 `无效的证明类型`。
- **comparison**：缺失缺省 `'>'`；`''`/`'='`/`'x'` → 400 `无效的不等号方向`。
- **整数字段**（m,n,u_val,au_val,bu_val,cu_val）：`^-?\d+$`（空格容忍、 `+3`/`abc`/`4.5` 拒）；m,n 全局界 **[0,30]**（与类型 cap 无关：arctan_q m=11 → 200、 e m=31 → `m过大`）；文案 `{field}必须是整数` / `{field}过小` / `{field}过大`。
- **u_val 下界按类型分裂**：pi/e `u_val=0` → 400 `u_val过小`；**gamma 接受 u_val=0** 并渲染 `\tilde{\infty}` 项（见 §7）。
- **分数字段**（a_val,b_val,c_val）：`^-?\d+(/\d+)?$` + 分母非零； `3.5`/`1e2` 拒（非 Fraction() 直解），` 47/120 ` 空格容忍，`-47/120` 接受； 文案 `{field}格式无效` / `{field}分母不能为0`。
- **coef / rational 不做任何解析校验，原文回显进方程**： `coef=abc`→`abc\pi`、`coef=2/4`→`\dfrac{2}{4}\pi`、`coef=01`→`01\pi`、 `coef=' 1 '`→` 1 \pi`、`coef=\frac{2}{4}`→`\frac{2}{4}\pi`； `coef=1`、缺失、`''` → 裸 `\pi`；**`coef=1/1` → `1\pi`**（n==d 折叠为 1）。 `rational` 同理原文回显：`3.5`→`3.5 - \pi`、`-3`→`-3 - \pi`、 `' 22/7 '`→`\dfrac{ 22}{7 }`（空格留在分子分母里）、`''`→` - \pi`、缺失→`0`。
- u_val 无上限：`u_val=10^20` → 200，分母原文嵌入方程。

## 6. 其它端点行为

- `GET /calculate` → **500**（非 405）；`PUT /calculate`、`DELETE /get_integral_image` → 500； `OPTIONS` → 200 空体；`/calculate/`、`/get_integral_image/`、`/en/`、任意未知路径 → 404 `{"error":"请求的页面不存在"}`；`/robots.txt` → 404。
- POST /calculate 只读表单：字段放 query string 或 JSON body 都读不到 → type 缺省 pi、comp 缺省 `>`、rational 缺失 → 400 `右侧有理数格式无效`。
- 重复字段 `type=pi&type=e` → 取**第一个**（pi），与 Flask form.get 语义一致。
- `/decompose_inequality`：缺 `problem`/空串/全空格 → 400 `请输入一个只包含一个 > 或 < 的不等式`； `foo>3` → 400 `当前乘积证明只支持基础常数的乘积`。
- `unified_form`：28 条专门探针 + golden 76 成功响应全部 `{}`——死字段。
- 姊妹页面：`/health`（健康计算器）、`/convex`（凹凸不等式计算器）→ 200 HTML， 属同站其它应用，不在复刻范围。
- `/` 与 `/en` **逐字节相同**（92562B，BOM 开头，尾部 `\n`），`/en?x=1` 同页。

## 7. 站端求解是数值近似的（保真边界）

> 本节的分歧已由 fidelity 统一模型收口（solve.prove 拦截 WD + 耗尽后 float64 复核，443e0d5 落地）——最终语义以 `fidelity-notes.md` 与 kernel-spec 方向判定三层为准，本节保留作探针原始记录。

以下分裂全部归因于站端 P 定号/方向判定在 float 精度下进行，本方是精确有理：

- **假命题、float 等值界**：`pi < float64(π)`、`e < float64(e)`（实际小 ~1e-16） → 站端搜不出恒负 P，耗尽报 `未找到`；本方精确搜出非正 P → `方向反了`。
- **真命题、~1e-32 超紧界**：pi/sin_q/e_q/ln_q `>` 方向 → 站端 float 噪声把某档 (m,n) 的 P 判成非正 → 误报 `方向反了`；本方耗尽报 `未找到`， e 型甚至直接证出 (m,n)=(11,12) 的 200。
- **gamma power=0 `>正数`**：站端先做严格方向预检（gap>0 → 方向反了 404）， gap=0 放行进核崩 500；本方在核内 `bound/abs(power)` 除零先崩 → 全 500。

## 8. gamma 渲染的特殊路径

- `u_val=0` 时站端照常渲染：第二段系数 `au/u` 除零 → 输出字面 `\tilde{\infty}` 项， 如 `\tilde{\infty} x^{2} (1-x)^{4} (18460 x + 2811)`。
- golden 里的退化组（m=n=0, a=1/4, c=1, u=0, coef=2）站端渲染为 `2γ - 1/2 = ∫[2(1/(1-x)+1/ln(x)-1/2)+1/2]dx > 0`——首段系数 2 提到括号外、 尾项 +1/2 是 a_val·coef 的展开形，与普通 gamma 方程模板不同。
